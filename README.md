# 🎉 派對遊戲（PartyGames）

一個網址、一個房間，想玩什麼就選什麼。房主開房間、朋友用 4 碼代碼或邀請連結加入，**進了房間之後再選要玩哪個遊戲**；玩完一個，回到大廳還可以直接換下一個，不用重新開房、重新邀請。

| 遊戲 | 人數 | 說明 |
| --- | --- | --- |
| 🎵 **猜歌大賽** | 1 人以上 | 聽動漫／流行歌／OST 的片段，搶先猜出來。各自播放或由「主畫面」播給大家聽，也可以當「旁觀者」即時看大家選了什麼。（單人模式不用開房間，純前端就能玩） |
| 🎙️ **配音大師** | 1 人以上 | 每人對著同一段影片用麥克風配音，再輪流播放、互相評分「搞笑」與「配音優異」，最後合成成品可下載 |
| 🗣️ **你說我猜** | 2 人以上 | 一人看題目、用嘴巴描述，另一人猜；限時內答對越多越好，大家輪流當出題者 |

## 流程

```
首頁（輸入暱稱）──建立房間／輸入代碼加入──▶ 房間大廳（玩家名單、遊戲選單、該遊戲的規則）
      │                                          │ 房主選遊戲、調規則、按「開始」
      └─ 🎵 單人猜歌（不用房間）                  ▼
                                            遊戲進行中 ──結束／房主按「回大廳」──▶ 回到大廳（可以換別的遊戲）
```

- 房主：第一個進房的人。房主斷線會自動移交；原房主 1 分鐘內回來可以拿回。房主能選遊戲、改規則、踢人、開始與結束遊戲。
- 斷線重連：手機鎖螢幕、切 App、重新整理都會自動回座；分頁被關掉也可以用**同樣的暱稱**重新加入。
- 伺服器重啟：大廳（選的遊戲與各遊戲的規則）會還原；進行中的**猜歌大賽**也會還原並讓大家自動重連；配音大師、你說我猜進行到一半時重啟，房間會回到大廳。

## 啟動

```bash
npm ci --omit=dev      # 只需要一個依賴：ws
npm start              # http://localhost:6713 （PORT、HOST 可用環境變數改）
npm test               # 單元測試（房間、計分、你說我猜、配音大師、猜歌大賽）
npm run simulate -- --bots 6   # 機器人用真的 WebSocket 跑完一整局猜歌大賽
```

玩家直接開 `http://你的主機:6713/`。環境變數（除了下面猜歌大賽那一節的表格，另外還有）：

| 環境變數 | 預設 | 說明 |
| --- | --- | --- |
| `CREATE_PASSWORD` | 空 | 設了之後，建立房間要輸入這組密碼（首頁會自動出現密碼欄）；加入房間不需要。公開上線建議設定 |
| `DUBBING_DIR` | `data/dubbing` | 配音大師的資料夾（底下有 `videos/`、`temp_audio/`、`outputs/`） |
| `DUBBING_KEEP_HOURS` | `24` | 錄音與合成成品保留幾小時，過期自動刪除（影片素材不會動） |
| `FFMPEG_PATH` | `ffmpeg` | ffmpeg 執行檔；沒裝 ffmpeg 配音大師還是能玩，只是沒有合成後的下載檔，頒獎時改用「原影片＋錄音」同步播放 |

## 🎙️ 配音大師

1. 把影片素材放進伺服器的 `data/dubbing/videos/`（mp4／webm／mov／mkv，可以分資料夾，房主在大廳像檔案總管一樣勾選，每部影片是一關）。素材很大，`data/dubbing/videos/` 已加進 `.gitignore`，不會進 git；目前放了兩部短片方便測試。
2. 每關：先自由「練習」，準備好按「開始正式錄音」→ 3 秒倒數 → 影片靜音播放、同時錄音（影片播完自動停止）→ 預覽、可重錄 → 「完成並鎖定」上傳。每關有限時（房主設，1–15 分鐘），時間到會自動鎖定並上傳目前的錄音；沒錄的人這關算 0 分。
3. 全員完成（或離線超過 10 秒不再等）後，作品隨機輪流播放，**其他人**評分「😂 搞笑」「🎭 配音優異」（1–5 顆星；作者不能評自己，只有一個人在線時例外，方便單人試玩）。房主可以按「不等了」略過還沒完成的人。
4. 全部關卡結束後，用 ffmpeg（伺服器要安裝：Debian／Ubuntu `sudo apt install ffmpeg`，Windows `winget install ffmpeg`）把每個人的配音合成進影片（影像直接複製、音訊轉 AAC），頒發「全場最搞笑」「配音最優秀」，列出總排行榜與所有作品（預覽／下載）。
5. 注意：**麥克風只有在 HTTPS 或 `localhost` 才能用**（瀏覽器規定）；公開上線一定要加 HTTPS（見下方部署）。錄音檔經 `POST /api/dubbing/upload` 上傳，nginx 要放寬 `client_max_body_size`（範例設定已加）。

## 🗣️ 你說我猜

- 題庫：`data/headsup.json`（`{"categories": {"分類名稱": ["題目", ...]}}`），房主選一個分類或「全部混合」。改完用 `systemctl reload`（SIGHUP）就會重新載入。
- 每「輪」兩個人：**出題者**看得到題目（題目只傳給他的裝置），用嘴巴描述、答對按 ✔、太難按 ⏭；**猜題者**看不到；其他人當觀眾。輪流讓每個人當一次（或兩、三次）出題者，猜題者是下一位；每輪答對的題數兩個人各得同樣的分。
- **誰來猜**（房主在大廳選）：**輪流**＝每個人輪流當出題者，猜題者是下一位；**指定**＝房主指定一位猜題者，其他人輪流當出題者讓他猜（兩個人玩就是經典的「一人說、一人猜」）。猜題者必須在線上才能開始；指定模式下猜題者累積所有輪的分數。
- 可設定：分類、每輪秒數（30–120）、每人當出題者幾次、誰來猜。出題者斷線超過 10 秒會提早結束該輪；中途加入的人先當觀眾。

## 新增一個遊戲

1. 伺服器：在 `server/games/` 寫一個繼承 `GameBase`（`base.mjs` 開頭有完整的介面說明）的 class，登錄到 `server/games/index.mjs`。遊戲只管規則與狀態，連線、重連、房主、踢人、選單都是房間（`server/room.mjs`）的事。
2. 用戶端：在 `js/games/<id>/` 寫一個模組（介面見 `js/hub/client.js` 開頭），登錄到 `js/games/index.js`。大廳會自動出現它的卡片與規則面板。
3. 訊息格式：用戶端 → 伺服器 `{t:'g', m:{…遊戲訊息…}}`，伺服器 → 用戶端 `{t:'g', g:'遊戲代號', m:{…}}`；房間層的訊息（`joined`、`hub`、`pick`、`settings`、`start`、`lobby`、`kick`、`leave`）與遊戲完全分開，不會互相打架。

## 程式結構

```
server/server.mjs   HTTP（靜態檔白名單、/healthz、/api/config）＋ WebSocket（/ws）＋ 房間存檔
server/room.mjs     房間：成員、房主、重連、踢人、選遊戲、存檔／還原
server/games/       各遊戲的規則（songguess／dubbing／headsup）
server/media.mjs    配音大師的檔案：影片清單、串流（Range）、錄音上傳、ffmpeg 合成、過期清理
js/main.js          入口：單人猜歌 ＋ 啟動 hub
js/hub/             首頁、大廳、連線（Net：自動重連＋對時）
js/games/           各遊戲的用戶端模組
css/                style.css（猜歌大賽）、hub.css、dubbing.css、headsup.css
```

# 🎵 動漫猜歌大賽（SongGuesser）

一個畫面、大家一起玩的團康猜歌遊戲。播放一小段動漫歌曲／OST，大家猜是哪部動畫，按一下空白鍵揭曉（歌名、作品、演唱／作詞／作曲）。

- 純前端，無需後端、無需打包，可直接放 GitHub Pages
- 音樂用 YouTube 嵌入播放（題庫只記錄影片 ID 與起始秒數，不存音檔）
- 題庫：動漫（OP／ED／插入曲／OST，`data/anime.json`）、**日本流行歌 J-POP（2015 年後熱門，`data/song.json`）**、遊戲 OST（`data/ost.json`）、電影配樂與歌曲（`data/movie.json`）

## 流行歌分類：日本／華語／英語（一曲兩用：猜歌名／猜歌手）

三個「歌名／歌手」類題庫：**🎤 日本流行歌**（2015 年後熱門為主，加少量經典，年代越久遠越少，`data/song.json`）、**🇹🇼 華語流行歌（台灣為主，含在台灣廣為人知的新馬港中歌手，`data/tw.json`）**、**🇺🇸 英語流行歌**（只收英文歌，經典＋熱門，`data/en.json`）。做法一樣，下面以日本流行歌為例；建置時 `--cat jpop`（日本）／`--cat tw`（華語）／`--cat en`（英語），歌單分別在 `data/seeds-jpop`、`data/seeds-tw`、`data/seeds-en`（英語歌的作品標題括號內是歌手的中文名，當選項小字）。

### 以日本流行歌為例

每首 J-POP 同一份題目有兩種問法：**猜歌名**（「這首歌的歌名是？」）或**猜歌手**（「這首歌是哪位歌手唱的？」）。設定畫面的「日本流行歌的猜法」可選：混合（每題隨機，預設）／只猜歌名／只猜歌手；揭曉時歌名與歌手都會顯示。8 選 1 的選項會跟著變（歌名選項小字是歌手、歌手選項小字是英文名）；多人模式的打字搜尋也會依題目換成歌名清單或歌手清單。J-POP 沒有 OP／ED 這類型，所以不受「歌曲類型」勾選影響；「同一部作品最多出現」＝同一位歌手最多出現幾首。

歌單在 `data/seeds-jpop/*.txt`（每位歌手是一個「作品」，歌曲一行），建置流程和其他題庫一樣，加上 `--cat jpop`：

```
# 米津玄師（Kenshi Yonezu） | 2020          ← 歌手（英文／羅馬字名）| 該歌手第一首的年份
JPOP | 感電 | 米津玄師 | y=2020 d=1          ← JPOP | 歌名 | 歌手 | y=發行年 d=難度（1 全民熟知／2 一般）
```

```bash
node scripts/resolve.mjs --cat jpop            # 查 YouTube（偏好官方頻道的 MV／官方音源，不要粉絲上傳、THE FIRST TAKE、現場版）
node scripts/resolve.mjs --cat jpop --retry-failed
node scripts/verify-movie.mjs --cat jpop       # 查核：影片標題／頻道／說明要同時有歌名與歌手
node scripts/build.mjs --cat jpop              # 產生 data/song.json
```

## 怎麼玩

| 操作 | 作用 |
| --- | --- |
| `空白鍵` | 播放中 → 揭曉答案；揭曉後 → 下一題 |
| `R` | 重播這一題的片段 |
| `→` | 跳過這題（不計入題數） |
| `↑` `↓` | 音量 ±5（也可拖曳滑桿；`M` 靜音／取消靜音；音量會記住） |
| `X` | 回報這題有問題（例如開頭不是音樂）：立刻跳過，之後在這台瀏覽器不再出現 |

設定畫面可選題數、播放長度、揭曉方式、難度、同一作品最多出幾首、歌曲類型。播放中有跑條；選「自動」揭曉時，播完前 5 秒會大字倒數並自動揭曉，揭曉後仍要手動按空白鍵進下一題。

## 多人模式（需要 Node 伺服器）

單人模式維持純前端（GitHub Pages 就能玩）。多人模式由 `server/` 的 Node 伺服器負責（房間、選遊戲、重連見上面「流程」）：在房間大廳選「猜歌大賽」後，大家**各自播放、各自作答**，伺服器判分並產生排行榜。

- **流程**：房主在大廳選「猜歌大賽」、設規則 → 開始 → 每題：全員預載影片 → 伺服器發「開播時間」（用 NTP 式對時，各裝置同時開播）→ 作答／鎖定 → 達門檻倒數或全員鎖定 → 揭曉（誰答對、各得幾分）→ … → 最終排行榜（頒獎台＋表格）→ 房主按「回房間大廳」（可以接著換別的遊戲）
- **作答**：8 選 1（預設），或打字搜尋作品名後點選；先選、再按「鎖定」（鍵盤：`1`–`8` 選、空白鍵／Enter 鎖定）。過程中大家看得到「已鎖定 n / N」與誰鎖定了（看不到選了什麼）
- **鎖定門檻倒數**：房主可選「過半玩家／全員／指定人數／不倒數」，達標後開始倒數 N 秒，倒數結束就揭曉；全員鎖定則立刻揭曉
- **計分**（房主選）：速度加成（600～1000，依作答速度）／固定分數（100）／速度＋連對加成；可開「答錯倒扣」。作答時間以**每個人自己實際開始聽到音樂**的時間起算，載入慢不吃虧
- **身分**（在大廳「我的身分」，每個人自己選，開始前隨時可改）：🎮 **參賽者**（自己作答拿分）／🖥 **主畫面**（接電視或投影機，只負責播放，不參賽）／👀 **旁觀者**（不參賽，但會即時看到每位參賽者目前選了什麼、有沒有鎖定；選擇題還會在選項上標出是誰選的。參賽者看不到彼此的選擇）。主畫面與旁觀者不算人數，也不計分；房主就算是主畫面或旁觀者，照樣能按下一題、強制揭曉、結束遊戲
- **播放方式**：預設各自播放（旁觀者也會一起聽）；也可選「**主畫面播放**」——需要有人把身分選為主畫面，只有主畫面出聲，手機只作答，避免同一個房間多支手機的回音
- **斷線重連**：手機鎖螢幕／切 App／網路閃斷都會自動重連，接回原本的座位——分數、連對、已選或已鎖定的答案都保留，播放中重連會從「應該播到的位置」接著播。分頁被關掉或瀏覽器把網頁殺掉也沒關係，**用同樣的暱稱重新加入**就會接回離線的座位（座位在線上時不能被搶）。離線玩家在大廳保留 10 分鐘、遊戲中保留 1 小時；離線超過 10 秒就不算進「鎖定人數」分母，不會卡住大家。房主斷線 1 分鐘內回來可拿回房主
- **其他**：同一分頁重新整理會自動回座並保留分數、房主離開自動移轉、踢人、中途加入（房主可關）、某人的影片無法播放時只跳過那個人（多數人失敗則換題）、音樂結束後可設作答寬限秒數、揭曉後可設自動下一題
- 電腦（寬螢幕，適合投影）與手機（直立）都有對應版面

### 啟動

啟動方式見上面的「啟動」。伺服器同時提供網頁，玩家直接開 `http://你的主機:6713/` 就能玩。

| 環境變數 | 預設 | 說明 |
| --- | --- | --- |
| `PORT` | `6713` | 監聽埠 |
| `HOST` | `0.0.0.0` | 監聽位址（放在反向代理後面建議 `127.0.0.1`） |
| `ALLOWED_ORIGINS` | 空 | 網頁與伺服器不同網域時（例如網頁在 GitHub Pages），允許連線的網頁來源，逗號分隔，如 `https://yourname.github.io`。同網域永遠允許 |
| `MAX_ROOMS` | `200` | 同時存在的房間上限 |
| `STATE_FILE` | `state/rooms.json` | 房間存檔位置（重啟還原用；systemd 的使用者要有寫入權限） |

### 部署（systemd + 反向代理）

- `deploy/PartyGames.service`：systemd 服務檔（內有安裝步驟；`systemctl reload PartyGames` 會熱重新載入題庫，`restart` 會存檔並在重啟後還原房間）
- `deploy/party.imatw.org.conf`：nginx 設定（80 port 反向代理到 127.0.0.1:6713，`/ws` 開 WebSocket；再用 `certbot --nginx` 加上 HTTPS）
- 公開上線一定要 HTTPS（瀏覽器在 https 網頁上只允許 `wss://`）
- `GET /healthz` 回傳房間數、人數、題數，可給監控用
- 只靜態提供 `index.html`、`css/`、`js/`、`data/*.json`；`data/cache`、`data/seeds`、`scripts` 不會對外

**網頁放 GitHub Pages、伺服器另外放**：把 `js/config.js` 的 `MULTI_WS_URL` 改成 `wss://你的網域/ws`，並在伺服器設 `ALLOWED_ORIGINS=https://<帳號>.github.io`。之後單人直接在 Pages 玩，多人也可以從 Pages 進（邀請連結會是 Pages 的網址）。

### 排查有人斷線

```bash
journalctl -u PartyGames -f      # 即時看；斷線會寫成「斷線 code=… 房間=… 玩家=…」
journalctl -u PartyGames --since "1 hour ago" | grep -E "斷線|心跳|錯誤"
curl -s http://127.0.0.1:6713/healthz
```

| 紀錄 | 意思 |
| --- | --- |
| `code=1006` / `1005` | 對方網路中斷或瀏覽器直接關掉（手機鎖螢幕、切換網路、關分頁最常見），客戶端會自動重連 |
| `心跳逾時` | 伺服器每 20 秒 ping 一次，對方 20 秒沒回應被中斷；多半是手機休眠。回來後會自動重連 |
| `code=1001` | 對方離開頁面 |
| `訊息過於頻繁` | 單一連線每秒超過 60 則訊息被斷線（正常玩不會發生） |
| `未捕捉的錯誤` / `處理訊息時發生錯誤` | 程式 bug；伺服器會記錄後繼續運作，不會讓所有人一起斷線。請把那段紀錄給開發者 |

若是**大家同時**斷線，常見是伺服器重啟——現在重啟後房間會自動還原、大家自動重連（見下方），所以看到的是短暫的「重新連線中」；若一直連不上才是別的問題： nginx 的 `proxy_read_timeout` 太短（範例設 120 秒，伺服器每 20 秒有心跳，正常不會觸發）；若前面還有 Cloudflare 等代理，要確認有開 WebSocket。

### 限制與注意

- **重啟不斷線**：房間狀態每 2 秒存到 `state/rooms.json`（可用 `STATE_FILE` 改位置），收到 `systemctl restart/stop`（SIGTERM）時會先存檔；重啟後自動還原房間，玩家的瀏覽器會自動重連（上方會顯示「連線中斷，正在重新連線…」），接回原本的座位、分數、已鎖定的答案，遊戲繼續。還原後的倒數與截止至少再給 12 秒讓大家連回來。若重啟時題庫已更新、進行中的那一題不見了，房間會回到大廳（分數歸零重來）。當機（沒機會存檔）最多遺失最後 2 秒的變化
- 房間存檔只存在這台主機；`state/` 已加進 `.gitignore`
- 手機（尤其 iOS Safari）的自動播放限制：每次進入遊戲的第一題，若瀏覽器不允許自動啟用聲音，畫面會提示「點一下這裡啟用聲音」，點一次之後整局都可以自動播放
- 題目與正解只存在伺服器，揭曉前不會傳給玩家；但影片 ID 一定要給玩家的瀏覽器才能播放，懂技術的人可以從網路請求查到影片網址（派對遊戲不處理這種作弊）
- 單人模式的「回報問題（X）」不影響多人；多人只有房主可「跳過本題」

## 題庫怎麼來、怎麼維護

題庫不是手寫 JSON，而是由「歌單」自動產生：

```
data/seeds/*.txt          歌單（以作品為單位，每首歌一行）
        │  node scripts/resolve.mjs   自動搜尋 YouTube、驗證可嵌入 → data/cache/resolved.json
        │  data/seeds/credits.tsv     以歌名補作詞／作曲（歌單沒填的才會補）
        │  data/overrides.json        手動調整（起點秒數、停用）
        ▼  node scripts/build.mjs
data/anime.json           遊戲實際讀取的題庫
```

### 歌單格式（`data/seeds/*.txt`）

```
# 鬼滅之刃（鬼滅の刃） | 2019
OP | 紅蓮華 | LiSA | l=LiSA c=草野華余子
ED | from the edge | FictionJunction feat. LiSA
OST | 竈門炭治郎のうた | 椎名豪 feat. 中川奈美
```

- `# 作品中文（日文） | 年份` 開始一部作品；同一部作品可以有多首歌
- 歌曲行：`類型 | 歌名 | 演唱 | 選填欄位`，類型為 `OP` / `ED` / `INSERT` / `OST`
- 選填欄位：`l=作詞` `c=作曲` `a=編曲` `q=自訂 YouTube 搜尋字` `t=別名/別名`（影片標題可能用的其他寫法，如英文名）`d=難度`（1 全民熟知，2 普通）
- 演唱寫 `?` 代表不確定
- 作詞／作曲也可以寫在 `data/seeds/credits.tsv`（`歌名|作詞|作曲|編曲`，沒有的填 `-`）；詞曲不是必填，沒有的欄位揭曉時不會顯示

### 自動從 MyAnimeList 擴充歌單

```bash
node scripts/fetch-mal.mjs --years 2012-2026 --works 240   # 抓人氣最高的作品與它們的 OP/ED → data/seeds/10-mal.txt
node scripts/resolve.mjs                                   # 幫新歌找 YouTube 影片
node scripts/build.mjs
```

- `data/seeds/mal-extra.list`：想指定一定要收的作品，每行寫一個英文／羅馬字作品名（或 MAL 編號）
- `node scripts/fetch-wiki.mjs`：從日文維基百科補插入歌／劇中歌與 MAL 漏掉的 OP/ED（寫到 `11-wiki.txt`）
- `data/seeds/names.tsv`：作品的台灣譯名對照（`日文原名 | 台灣譯名`），只影響顯示
- 各季會依 Prequel 合併成同一部作品；中文名取自 Wikidata，沒有就用英文名
- 已經出現在其他歌單的作品／歌曲不會重複；`10-mal.txt` 是自動產生的，不要手動改
- 前 90 名人氣作品難度 1，其餘難度 2

### 新增題目

1. 在 `data/seeds/` 裡的 `.txt`（或新建一個）加上作品與歌曲
2. 執行：

```bash
node scripts/resolve.mjs     # 只會處理新加的歌；--retry-failed 重試失敗的
node scripts/build.mjs       # 產生 data/anime.json
```

3. `data/cache/missing.txt` 會列出找不到可嵌入影片的歌，可改 `q=` 搜尋字再重跑，或直接刪掉

### 微調起點、停用題目

開 `preview.html`（需 http 伺服器）：逐首試聽、修改起點秒數（或在播放中按「設為目前位置」）、停用有問題的題目。按「複製 overrides.json」貼進 `data/overrides.json`，再跑 `node scripts/build.mjs` 就會永久生效（不會被重新建置覆蓋）。

> 猜歌時一律從影片開頭播放；按下揭曉後，若有 YouTube「最多重播」資料，會跳到那個位置（通常是副歌）繼續播，沒有資料的影片就接著播（題庫欄位 `revealStart`，可在 `overrides.json` 針對單題改）。所以挑影片時優先選「一開始就是音樂」的類型（歌詞版、ノンクレジット OP/ED、官方音源），`preview.html` 勾「只看需確認的」是不屬於這類、開頭可能有對白或劇情的影片。真的需要從別處開始，可在 `overrides.json` 針對單題設定 `start`。

## 已知限制

- 影片來自 YouTube，日後若被刪除、設為私人或禁止嵌入，遊戲會自動跳過那一題；可重新執行 `resolve.mjs --force` 更新
- 部分影片開頭可能有 YouTube 廣告（取決於影片與使用者帳號）
- 詞曲唱資料來自歌單與 `credits.tsv`，不是每首都有；缺的欄位揭曉時不會顯示
- 手機／平板第一次播放需要點擊畫面（瀏覽器自動播放限制）
